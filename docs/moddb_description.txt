<h2>What it is</h2>
<p><strong>Optimum</strong> is a client-side fork of Vintage Story made for players who want smoother frames without changing how the game plays. Servers do not need anything installed. Players connect with <strong>Optimum</strong> the same way they would with a stock client. Worlds, accounts, and mods carry over unchanged.</p>
<p>Optimum decompiles the official client and patches the source to build a set of optimized "donor" assemblies. Its own launcher then applies those changes with Cecil directly into copies of your game's assemblies the first time you run it, and caches the result so every launch after that is instant. No Harmony overhead. No mod loader in the way. Your vanilla files are never modified. The engine itself runs faster.</p>
<h2 style="width: 100%; height: 200px; background-color: #a8e6cf; color: black; display: flex; align-items: center; justify-content: center; font-family: sans-serif; font-size: 1.1em; border-radius: 10px; padding: 20px; box-sizing: border-box; text-align: center; border: 2px solid #8cd1b8; box-shadow: 0 4px 6px rgba(0, 0, 0, 0.05);"><strong>Optimum replaces OptiTime. Disable or remove OptiTime in your Mods folder. Synergy and Tungsten still work.</strong></h2>
<p>&nbsp;</p>
<p>Optimum is not a settings tweak or a config mod. It is a replacement client runtime focused on the places where vanilla leaves performance on the table:</p>
<ul>
<li>frame pacing that eliminates micro-stutter</li>
<li>FSR 1.0 upscaling: render at reduced resolution, upscale to native with AMD's edge-aware filter (Quality/Balanced/Performance presets)</li>
<li>shader passes that do less redundant work</li>
<li>entity rendering that skips what the player cannot see</li>
<li>entity light batching that resolves chunk lights in bulk (42-67% faster at 32+ entities)</li>
<li>shader state cache that uploads uniforms once per pass instead of per entity (83% reduction)</li>
<li>physics and audio updates that skip what the player cannot notice</li>
<li>chiseled block LOD that drops 83x vertices at distance</li>
<li>foliage shadow skip in the far cascade</li>
<li>particle emitters gated by distance</li>
<li>map page cache: 8x8-chunk GPU texture array with BC7 compression and disk persistence, replacing per-component draws with one draw call</li>
<li>lock contention reduction (11 locks converted to System.Threading.Lock)</li>
<li>GC pressure reduced in tight loops</li>
<li>configurable distance gates for shadows, repulsion, particles, and chiseled blocks</li>
<li>bugfix for a long-standing client issue (#9710)</li>
</ul>

<h2>Where Optimum Helps</h2>
<h3>Frame Timing</h3>
<p>Vanilla uses Thread.Sleep for frame pacing, which overshoots on most systems and causes micro-stutter. Optimum replaces it with a hybrid sleep/yield/spin loop that hits target frame times with sub-millisecond accuracy. When you alt-tab, the client drops to 30 FPS so your GPU can idle.</p>
<h3>Rendering and Shaders</h3>
<p>Entity shadows stop drawing beyond 80 blocks (configurable). Vegetation skips the far shadow cascade entirely (togglable). The held-item dynamic light scales its radius with your view distance instead of illuminating a fixed 120-block sphere. Animated blocks like forges and querns tick their animations less often at distance, in three LOD tiers. Chiseled blocks render as solid cubes beyond a configurable threshold (83x vertex reduction for distant microblock builds). Entity render calls skip before computing model matrices when squared distance exceeds view distance. Entity light lookups batch all visible entities into one pass per chunk, eliminating per-entity lock contention and allocation. Shader state (view matrix, wave counter, animation UBO) uploads once per render pass; each renderer reads the cached result instead of re-uploading. FSR 1.0 renders the world at 67-85% resolution and upscales to native with AMD's EASU edge-aware pass plus RCAS sharpening: more FPS on GPU-bound systems in exchange for slight softness. Native (1.0x) disables it.</p>
<h3>Entity Updates</h3>
<p>Client-side repulsion physics skip entities beyond a configurable range (default 64 blocks). Entity animation checks test distance before frustum, so the cheaper test fails first and the expensive one never runs. Name-tag HUD elements share one frustum result per entity instead of recalculating individually.</p>
<h3>Audio and Weather</h3>
<p>Wind calculations cache for 4 frames (togglable). Particle emitters beyond 48 blocks stop spawning (togglable). Ambient sound position updates skip when the player stands still. Fly sound volume updates skip when the change is below 1%. None of these are perceptible, all of them save work every frame.</p>
<h3>Memory</h3>
<p>Ten client-side locks converted from Monitor.Enter to System.Threading.Lock, which uses a single interlocked CAS on the uncontended path. Particle tick loops reuse BlockPos instead of allocating per iteration.</p>
<h3>Map</h3>
<p>Vanilla's map layer uploads and draws terrain per map chunk. Optimum groups chunks into 8x8 pages, persists them to disk as compressed RGBA, uploads them into a single large GPU texture array with LRU eviction, and draws the whole visible set in one call instead of one draw per component. Pages compress with BC7 when the GPU supports it. An opt-in mode fills unexplored map areas with an approximation derived from the world seed and the terrain data the client already has, so the map reads as populated instead of blank before you've explored.</p>
<p>&nbsp;</p>
<h2>Bugfixes</h2>
<ul>
<li><strong>#9710</strong>: mouse wheel at low sensitivity keeps float precision. Dead scroll zones gone.</li>
<li><strong>Mod crash containment</strong>: an exception thrown by a mod while the creative inventory search index builds no longer crashes the whole client. The item falls back to a name-only search entry and the offending mod is named in the log.</li>
<li><strong>Background FPS focus flicker</strong>: the background limiter no longer fires during world load or when the window flickers focus state. A 300ms debounce prevents false triggers.</li>
<li><strong>Frame pacing on low-core machines</strong>: the spin-loop tail now gates behind a core count check. Machines with 5 or fewer cores fall back to Yield-only pacing. Windows builds call <code>timeBeginPeriod(1)</code> for 1ms timer resolution.</li>
<li><strong>VS Roofing LOD</strong>: roof blocks that use <code>BlockEntityMicroBlock</code> no longer get replaced with a solid cube at distance. The chisel LOD checks <code>canChisel</code> before substituting.</li>
<li><strong>Linux font rendering</strong>: Optimum no longer ships a recompiled <code>cairo-sharp.dll</code>. The vanilla pristine copy ships as-is, fixing glyph shape differences on Linux.</li>
<li><strong>Chiseled block shadows</strong>: the distant full-cube LOD proxy was reaching the shadow map at any distance, so chiseled blocks cast full-block shadows even up close. Fixed with distance-aware shadow culling.</li>
<li><strong>Crucible rendering black above 900&deg;C</strong> (#9718): incandescence glow now routes through its own uniform instead of saturating the light vector, matching the forge renderer.</li>
<li><strong>Settings dialog crash on tab switch</strong>: a mismatch between the panel background size and the underlying draw surface could overrun a native pixel buffer. The two now always resize together.</li>
<li><strong>Prospecting pick node search silently did nothing</strong>: Node Search Mode never printed "no ore nearby" or any quantity result (density search still worked). Two fields added for the node-search optimization had no initializer run under the runtime patcher, so the first lookup threw before any chat message could be sent. Fixed by lazily initializing on first use.</li>
<li><strong>Animation lookups allocated a string every frame</strong>: every animated entity's animation-state lookup lowercased its animation code on every call instead of using a case-insensitive comparer. Fixed at the API level, removing a per-frame, per-entity allocation.</li>
</ul>
<p>&nbsp;</p>
<h2>Experimental: Trader/Villager Stutter Fix (opt-in)</h2>
<p>Dressed NPCs (traders, villagers) re-tesselating their shape and gear could cost 50-230ms in a single frame, most visible when several load in at once (a caravan arriving, entering a village). Three settings target this, all default OFF pending broader testing, configurable only via <code>ModConfig/optimum.json</code> (no in-game toggle yet):</p>
<ul>
<li><code>EntityTesselationFrameBudget</code>: caps how many dressed-entity re-tesselations run in a single frame, spreading the rest over following frames instead of front-loading them all at once.</li>
<li><code>EntityOutfitShapeCache</code>: reuses the fully assembled gear shape and resolved textures for outfit combinations already built once, instead of re-parsing every gear piece's shape JSON and re-walking the step-parenting element tree per entity.</li>
<li><code>EntityOutfitAnimatorCache</code>: reuses the built animator (pose graph) for entities sharing the same outfit combination, instead of rebuilding it from scratch on every re-tesselation - the largest remaining cost in this path.</li>
<li><code>EntityOutfitTexturePrewarm</code>: inserts every outfit variant's textures into the atlas once during the loading screen instead of on first encounter mid-gameplay, where a texture atlas cache miss can cost 100ms+ in a single frame.</li>
</ul>
<p>Together, measured via <code>.optimum stutterwatch</code>, these reduced per-call cost from 58-230ms down to 7-9ms in real gameplay testing.</p>

<h2>Settings</h2>
<p>Optimum adds an <strong>Extra</strong> tab in client settings with fourteen switches, three sliders, and a render scale dropdown. Switches default to ON; render scale defaults to Native:</p>
<ul>
<li>Background FPS Limit (30 FPS when unfocused)</li>
<li>Smooth Frame Pacing</li>
<li>Entity Shadow Cull + distance slider (20-200 blocks)</li>
<li>Entity Repulsion Gate + distance slider (16-128 blocks)</li>
<li>Dynamic Light Scale</li>
<li>Animated Block LOD</li>
<li>Skip Foliage Far Shadows</li>
<li>Throttle Wind Updates</li>
<li>Reduce Distant Particles</li>
<li>Simplify Distant Chiseled Blocks + distance slider (32-256 blocks)</li>
<li>Smart Chunk Culling</li>
<li>Reuse Light Scans</li>
<li>Batch Entity Light Reads</li>
<li>Cache Entity Shader State</li>
<li>Render Scale (FSR): Native (1.0x), Quality (0.85x), Balanced (0.77x), Performance (0.67x)</li>
</ul>
<p>Settings persist to ModConfig/optimum.json. Shader optimizations and zero-tradeoff code paths run unconditionally because they produce identical output to vanilla.</p>

<h2>Compatibility</h2>
<p>Use the Optimum release that matches your Vintage Story version. Players do not need to install anything on the server. Most client mods work, but Optimum changes deeper client internals than a regular mod. If a mod hooks into rendering or entity update loops, test it before trusting it on a long session.</p>
<p>Vintage Story 1.22.5 is the default target and the fully verified path. Vintage Story 1.22.6 is supported experimentally: install Vintage Story 1.22.6 first, then point the Optimum installer at it (<code>install-linux.sh --version 1.22.6</code>, <code>install-windows.cmd</code> auto-detects it, <code>install-macos.sh</code> asks to confirm the version). Optimum does not update your Vintage Story install for you. The 1.22.6 patches are reconstructed from the compiled client rather than from Anego's published source, so treat it as a stopgap until upstream source catches up.</p>

<h2>Install</h2>
<p>Optimum ships as source. You build it once against your installed copy of Vintage Story, and the installer produces a self-contained Optimum folder with a launcher that patches copies of the engine assemblies the first time you run it, then caches the result for instant launches after that. Your original Vintage Story install is never touched.</p>
<h3>Windows (GUI Installer)</h3>
<p>Download the <code>Source code (zip)</code> from the <a href="https://github.com/Zaldaryon/Optimum/releases/tag/v0.3.5">v0.3.5 release page</a>, extract it, and double-click <code>install-windows.cmd</code>. The installer handles prerequisite checks, decompile, patch, build, package, and registry install with a single click, and builds against whichever Vintage Story version (1.22.5 or 1.22.6) it finds installed.</p>
<h3>Manual Build</h3>
<ol>
<li>Download the source for the release that matches your Vintage Story version (the source zip or tar.gz on the release page).</li>
<li>Extract it and run the build script for your platform:
<ul>
<li>Windows: <code>powershell -ExecutionPolicy Bypass -File build-windows.ps1</code></li>
<li>Linux: <code>./scripts/install-linux.sh</code> (interactive installer with prerequisite checks)</li>
<li>Linux (AppImage): <code>make package-appimage</code> (single portable executable)</li>
<li>macOS: <code>./build-macos.sh</code></li>
</ul>
</li>
<li>Launch the resulting <strong>Optimum</strong> client.</li>
</ol>
<p>Linux and macOS builds run with bash. No PowerShell required for those platforms.</p>
<p>Your existing data folder and worlds work without migration. Optimum reads from the same data path as vanilla by default, or a separate one if you configure it at launch.</p>
<p><strong>DO NOT INSTALL THIS AS A GAME MOD.</strong> It is not a .zip that goes in your Mods folder. It is a standalone client that patches copies of the engine DLLs at launch.</p>
